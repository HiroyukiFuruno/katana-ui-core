## 監査の観点

各 UI は最低限、次の 3 点を UI ごとに埋める。

1. 何が不足しているのか
   - 要件欠落、core API 欠落、Storybook harness 欠落、実操作 test 欠落、guard 欠落、既知不具合を分ける。
2. どうあるべきなのか
   - 画面上の見え方、操作、状態遷移、イベント、コールバック、無効/readonly/focus/hover/scroll/resize の仕様を明文化する。
3. 実装アプローチ、設計、階層設計は妥当か
   - core public API で実部品が構築されているか、Storybook 専用 state/hit-test が本体動作を代替していないか、共通 engine に寄せるべき処理を UI 個別に持っていないかを見る。

## 判定ラベル

- `失敗`: 自動テストで実証済みの不具合がある。
- `部分通過`: 一部の自動テストは通るが、UI 要件全体の証跡ではない。
- `未検証`: 接続は見えても、実操作の自動証跡がまだない。
- `監査対象`: 過去指摘、設計リスク、または direct test gap があり、深掘り対象。

## 実装に入る前の DoR

この台帳の各 UI 行について、実装前に次を埋める。

1. 現在の core public API と Storybook 構築箇所。
2. 現在の state/action/event/callback の所有者。
3. 必須操作種別。
   - pointer
   - keyboard
   - scroll
   - drag
   - context menu
   - focus
   - hover
   - resize
4. 既存 test と不足 test。
5. Storybook 専用 state/hit-test/preview が本体動作を代替している箇所。
6. 自動検知すべき失敗条件。

## 実装方針

1. まず 77 UI manifest を作る。
   - UI 名、group、public props/options、state、action、event、callback、必須操作、対応 test を machine-readable にする。
2. `storybook-interaction-smoke` を manifest 駆動にする。
   - marker 集計ではなく、P0 操作を実行する。
   - 1 UI でも未検証なら失敗させる。
   - 2026-06-13 時点で live audit は 77 UI の preview click / binary row click を記録するが、manifest 上の `verified` は 0 件のため smoke は赤で固定されている。
3. Storybook は harness に限定する。
   - core public API で実部品を構築する。
   - Storybook 専用 state や page 専用 hit-test は、実部品の代替にしない。
4. 共通 engine を先に定義する。
   - clickable/button
   - text entry
   - binary choice
   - selection/list/tree
   - overlay/menu/context menu
   - tabs
   - scroll/resize/drag
   - layout alignment
5. UI 個別実装は薄くする。
   - 個別 UI は props/options と rendering 差分を持つ。
   - state transition、hit-test、keyboard、scroll は共通 engine に寄せる。

## 4,000 文字以内の目標文

KUC Storybook を静的な絵ではなく、core public API で構築した実部品 harness として復旧する。現時点で 77 page は requirements / preset / Inspector / dedicated rendering に接続済みで、headless scenario と smoke は通るが、これは実操作保証ではない。`window_interaction` は `toggle` の `disabled` preset が body diff 0 で失敗しており、全 UI 完了扱いは禁止する。まず `docs/storybook-77ui-deep-audit-ledger.md` を監査台帳として、77 UI それぞれに「不足」「あるべき姿」「設計/階層妥当性」を埋める。証跡がない UI は未検証として残す。次に machine-readable manifest を作り、各 UI の public props/options、state、action、event、callback、pointer / keyboard / scroll / drag / context menu / focus / hover / resize の必須操作、対応 test を紐づける。Storybook は core 部品を動かす harness に限定し、Storybook 専用 state、Inspector だけの変化、preset label だけの変化、core public API を通らない動作代替を guard で禁止する。実装は共通 engine を先に整備し、button/clickable、text entry、binary choice、selection/list/tree、overlay/menu、tabs、scroll/resize/drag、layout alignment を再利用する。完了条件は全 77 UI が台帳上で実証済みとなり、manifest 駆動の interaction smoke、window_interaction、requirement gate、core contract、guard が通り、ユーザーが手で触らないと壊れ方が分からない状態が残っていないこと。
