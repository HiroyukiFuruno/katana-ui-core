# 設計 - CodeDiff

## 概要

CodeDiff は、変更前と変更後のコード断片を表示する読み取り専用の画面部品（widget）とする。
上位アプリは文字列と行情報を渡すだけで、CodeDiff は差分モデルを構築し、指定された表示形式で描画する。

## 利用入口（API）の方針

`composite/code_diff` 配下に責務を分けて実装する。

- `types.rs`
  - `CodeDiffSource`
  - `CodeDiffProps`
  - `CodeDiffMode`
  - `CodeDiffSplitOrientation`
  - `CodeDiffLineKind`
  - `CodeDiffTextRange`
  - `CodeDiffModel`
- `model.rs`
  - 行単位の差分構築
  - 末尾改行と空行の扱い
  - 行数検証
- `highlight.rs`
  - 変更行同士の文字単位差分
- `split_model.rs`
  - 分割表示用の左右・上下ペアリング
- `view.rs`
  - CodeDiff 本体表示
- `row.rs`
  - 行番号、記号、コードセル、省略行の描画
- `style.rs`
  - テーマトークン（theme token）に沿った追加・削除・通常・省略の色解決
- `tests.rs`
  - 差分モデルと表示条件の単体テスト

公開する利用入口（API）の方向性:

```rust
pub struct CodeDiffSource {
    pub text: String,
    pub first_line_number: usize,
    pub line_count: usize,
}

pub enum CodeDiffMode {
    Split,
    Inline,
}

pub enum CodeDiffSplitOrientation {
    Horizontal,
    Vertical,
}
```

`CodeDiffProps` は、変更前、変更後、初期表示形式、初期分割方向、省略方針、見出し表示の有無を持つ。
表示形式が内包表示（inline）の場合、`CodeDiffSplitOrientation` は保持しても描画には使わない。

`line_count` は、末尾改行で生じる空行も含めた表示上の行数として扱う。
`text` から算出した行数と一致しない場合は、表示をごまかさずエラーとして扱う。
空文字列の `line_count` は `0` とし、片側だけが空の場合は全行追加または全行削除として扱う。
文字範囲は Rust のバイト位置ではなく、表示文字単位の位置（index）で扱う。

## 差分モデル

Katana の `diff_review` を参考に、行単位は最長共通部分列（LCS）、変更行の文字範囲は文字単位の最長共通部分列（LCS）で求める。
変更前だけにある行は削除、変更後だけにある行は追加として扱う。
削除行と追加行が近い位置にある場合は1つの変更ペアとして扱い、差分箇所だけを濃く強調する。
空行だけの弱い基準行（anchor）を挟む変更でも、Katana の `model_pairing_tests` と同じように類似行を対応付ける。

空行と末尾改行は表示上の差分として残す。
たとえば、変更後だけ末尾改行が増えた場合は、追加された空行として `↵` 相当の表示を持つ。
分割表示で片側に対応行がない場合は、反対側に薄いプレースホルダーを出し、追加・削除の位置関係を崩さない。
変更がない場合は、空表示にせず「差分なし」と分かる状態を表示する。

## 表示仕様

### 分割表示（split）

- 左右表示では、変更前を左、変更後を右に置く
- 上下表示では、変更前を上、変更後を下に置く
- どちらも行番号を表示する
- 対応する変更行は同じ行位置にそろえる
- 片側だけに存在する行は、もう片側にプレースホルダーを表示する
- 左右表示では中央境界を常時見える仕切りとして描画する
- 左右表示で長い行を横スクロールした場合、変更前と変更後の横位置を同期する
- 左右表示は比率変更を扱えるようにし、上下表示は上下の境界が分かる見た目にする

### 内包表示（inline）

- 1列に削除行、追加行、変更なし行を並べる
- 変更ペアは削除行の直後に追加行を置く
- 内包表示では、左右表示・上下表示の指定は無効とする
- 画面上の切り替え操作でも、分割方向の操作は押せない状態にする

### ハイライト

- 追加行は追加色、削除行は削除色で行全体を薄く強調する
- 実際に変わった文字範囲は、行全体より濃い背景で強調する
- 空白文字の変更は見落とさないよう、変更範囲内の空白（space）は `·`、タブ（tab）は `→`、空行は `↵` として表示する
- 削除側の局所ハイライトは、Katana の波線表現を参考に、消える範囲であることが分かる見た目にする

## 省略表示

変更点から離れた未変更行は、既定で `非表示 N 行` のような省略行として表示する。
利用者が省略行を押すと、その未変更ブロックを展開する。
省略行は横長バーとして表示し、閉じている時は開く、開いている時は閉じる、という1つのクリック領域だけを持つ。

オプション（option）として以下を持つ。

- 省略を使うか
- 既定で展開して表示するか
- 変更前後に常に残す文脈行数

## Storybook 確認

Storybook では、次を同じページ内で確認できるようにする。

- 左右の分割表示
- 上下の分割表示
- 内包表示
- 分割方向の無効化
- 追加のみ
- 削除のみ
- 差分なし
- 類似行が空行を挟む変更
- 1行内の文字変更
- 空白文字の変更
- 日本語など複数バイト文字を含む変更
- 末尾改行の追加・削除
- 長い未変更行の省略と展開
- 左右分割の長い行と横スクロール同期
- 明るい表示（light） / 暗い表示（dark）のテーマ

## 受け入れ方針

見た目だけの静的サンプルでは完了扱いにしない。
差分モデルの単体テスト、Storybook の操作確認、`just storybook-check`、`just check` を完了条件に含める。
